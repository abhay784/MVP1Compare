HTML SHELL RULES

  1. Reproduce the template's visual style as faithfully as possible from the
     page images:
       - fonts (use generic web-safe fallbacks: "Helvetica, Arial, sans-serif"
         if the template uses a sans-serif; "Times New Roman, Times, serif"
         if serif; "DejaVu Sans Mono, monospace" for monospace),
       - colors (header bars, table backgrounds, accent rules, severity
         color codes if visible),
       - table borders and spacing,
       - heading sizes and weights,
       - page margins (use @page CSS — A4 by default).
     Do not invent ornament that is not in the template. Do not omit ornament
     that IS in the template (e.g. company-style header bands, signature
     blocks, footer rules).

  2. The HTML must be a single self-contained document. All CSS goes in a
     <style> block in <head>. No external resources, no <link>, no <script>,
     no external images. (Dynamic images are injected via the tokens.)

  3. Wherever DYNAMIC CONTENT goes, insert exactly one of these token
     strings (each on its own where appropriate). Do not invent new tokens
     and do not modify the spelling.

       [[TITLE]]            — the report title (one line of text)
       [[PART_NUMBER]]      — the part number string
       [[JOB_ID]]           — the job UUID string
       [[GENERATED_AT]]     — the ISO timestamp string
       [[NOTES]]            — the free-text user notes block; may be empty
       [[SUMMARY]]          — the severity-count tile row (HTML table/divs)
       [[TITLE_BLOCK]]      — the title-block field comparison table
       [[REVISION_BLOCK]]   — added/removed revision entries
       [[DRAWINGS]]         — the side-by-side annotated page images
       [[CHANGES]]          — the per-view change tables

     Place each token in the location where the matching content appears on
     the template (e.g. if the template has a "Summary of Changes" panel at
     the top, put [[SUMMARY]] there). If the template has a section the
     comparison data does not need (e.g. "Approvals", "Signatures"), keep
     that section's heading and lay out empty signature lines or "_______"
     placeholders — but do not insert any of our tokens there.

  4. For [[CHANGES]], the surrounding HTML structure (heading, intro text,
     table CSS classes) should come from the template. The TABLE itself is
     emitted by the renderer, using the columns you specify in
     `change_table.columns`. Place [[CHANGES]] where the table goes; the
     renderer will substitute a full <table>...</table>.

  5. Severity color CSS classes — the renderer expects these class names to
     exist if you want severity-colored rows/cells:
         .sev-CRITICAL, .sev-SIGNIFICANT, .sev-MINOR, .sev-UNCERTAIN
     Define them in the <style> block to match the template's coloring
     (subtle backgrounds, e.g. light red / amber / grey / yellow).

  6. Watermark line: include at the very end of <body>
         <p class="watermark">⚠ AI-generated — requires human verification.</p>
     ...styled in a small italic red to match the disclaimer convention.

CHANGE TABLE RULES

  Look at the template's change/issue/finding table (if it has one) and
  populate `change_table.columns` with the columns you see, IN ORDER, using
  the customer's exact header wording. For each column, classify its role:

     severity     — class/severity/impact column
     field        — what changed (dimension, note, hole, etc.)
     orig_value   — "was", "from", "before", "original" value
     revised_value— "now", "to", "after", "revised" value
     zone         — drawing zone identifier (e.g. "A4", "B-7"); often
                    appears as "Zone", "Location", "Area", or similar
     confidence   — model confidence; rare on customer templates
     description  — "description", "rationale", "comments", "notes about
                    change", or similar
     other        — anything else; will render as blank

  If the template has NO change table at all, default to:
     [
       {"header":"Class",       "role":"severity"},
       {"header":"Item",        "role":"field"},
       {"header":"Was",         "role":"orig_value"},
       {"header":"Now",         "role":"revised_value"},
       {"header":"Description", "role":"description"}
     ]
  and set has_zone_column=false.

  Set has_zone_column=true ONLY if at least one column has role="zone".

SEVERITY LABELS

  If the template uses customer-specific severity terminology (e.g. Class A
  / B / C, Priority 1/2/3), map them. Otherwise use the defaults shown above.
